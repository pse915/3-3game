# 실행과 학습 기록 운영 안내

## 설치와 실행

Python 3.11 이상에서 프로젝트 루트의 다음 명령을 사용합니다.

```sh
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

교사 화면과 서버 저장 검증에는 Streamlit 실행이 필요합니다. 정적 HTTP 서버로 Canvas만 확인하는 경우 서버 저장과 교사용 대시보드는 제공되지 않습니다.

## 보안 설정

`.streamlit/secrets.example.toml`을 참고해 배포 호스트에만 `secrets.toml`을 만듭니다. 교사 비밀번호는 임의의 긴 값으로 바꾸고 Google 서비스 계정에는 대상 시트 편집 권한을 부여합니다. 실제 비밀키, 복구 토큰, SQLite 데이터베이스와 학생 기록을 GitHub에 업로드하지 않습니다. 교사 화면은 서버 비밀번호 확인 후에만 열리며, 개발용 URL 매개변수로 교사 인증을 생략하지 않습니다.

복구 토큰이 포함된 기기 내보내기 JSON은 개인 보관용입니다. 전체 학급이 공유하는 폴더에 올리지 마세요. 이름·전화번호·실제 가족 상황처럼 수업에 불필요한 개인정보는 이유나 소감에 입력하지 않도록 안내합니다.

## 저장 상태와 복구

기기 저장과 서버 SQLite 저장을 유지합니다. 새 자유 활동 기록은 기존 v2 저장 봉투 안의 선택 항목 `life`로 저장되므로, 이 항목이 없는 기존 v2 체크포인트도 서버에서 검증할 수 있습니다. 서버는 기존 v1 기록도 보존하며 v1을 새 이야기로 자동 변환했다고 주장하지 않습니다.

서버가 먼저 SQLite에 저장하고 outbox를 통해 Sheets에 전송합니다. 전송 실패 시 2초부터 최대 256초의 대기 시간을 적용해 이후 저장 요청에서 재시도합니다. 별도 백그라운드 작업이 아니므로 사용자가 모두 접속을 종료하면 재시도도 진행되지 않습니다. 화면에서 Sheets 전송 지연과 로컬 전용 저장을 안내합니다. 교사는 대시보드의 전송 대기/재시도 대기 상태를 확인할 수 있습니다.

`checkpoints` 워크시트는 `id, token_hash, revision, payload` 네 열을 유지합니다. 같은 익명 ID의 중복 행이 존재하면 최신 정수 revision을 선택하고, 복구할 때 손상된 최신 기록은 이전 유효 기록으로 되돌아갑니다. 이미 전송된 revision을 재전송해도 새 행을 추가하지 않습니다. 긴 payload는 `gzip:` 접두어의 압축 데이터로 저장될 수 있으며 기존 JSON payload도 계속 복구합니다. 서버 내부 잠금은 한 프로세스 안의 요청을 보호합니다. 여러 Streamlit 프로세스가 하나의 시트에 동시에 새 ID를 쓰는 분산 트랜잭션은 제공하지 않습니다.

복구할 때 같은 토큰으로 검증되는 SQLite/Sheets 기록 중 최신 revision을 사용합니다. Streamlit Community Cloud의 임시 디스크는 영구 보관소가 아니므로 시트 전송 성공 여부와 기기 백업 파일을 함께 확인합니다. 교사 대시보드는 현재 서버 SQLite 기록을 조회하며, Sheets의 모든 과거 기록을 자동 일괄 가져오는 기능은 제공하지 않습니다.

## 교사용 대시보드

참여·다이어리 완성·활동 시간을 보여주고, 익명 기록마다 핵심 선택·자유 활동 수·돌발 사건 수·미래 모습·현재 실천 계획·소감을 확인합니다. 개별 기록을 선택하면 활동과 사건의 선택 이유, 결과, 학습 개념, 다음 계획을 확인할 수 있습니다. 미래 모습은 현재 자원과 경험에 따른 설명이며 학생의 성적이나 인생의 우열을 뜻하지 않습니다.

## 이번 수정의 검증 범위

```sh
python -m unittest discover -s tests -v
python -m py_compile app.py server/storage.py server/sheets.py
```

기존 Python 5개 테스트와 확장 6개 테스트를 실행해 통과했습니다. 확장 검증은 기존 저장 봉투 호환, 활동 자원·이유·계획 검증, 외모 설정과 발견 조각 검증, Sheets 중복 전송 방지, 최신 중복 행 복구, 손상 payload 폴백, 긴 payload 압축 복구를 포함합니다. Sheets 테스트는 모의 워크시트를 사용했습니다.

로컬 Streamlit 서버를 실제 브라우저에서 실행하고 활동 체크포인트가 서버의 저장 응답을 받는 것을 검증했습니다. 이 검증에서는 Google Sheets를 연결하지 않았습니다. 별도의 Streamlit AppTest 시도는 환경에서 응답이 지연돼 성공으로 처리하지 않았습니다. 실제 Google Sheets 계정과 운영 배포 환경은 이번 실행에서 검증하지 않았습니다.
