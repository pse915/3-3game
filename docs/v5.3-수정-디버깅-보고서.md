# 미래 다이어리 v5.3 수정·디버깅 보고서

기준 원본: 사용자가 제공한 2.zip의 seorabeol 프로젝트. 기존 Streamlit 진입점 app.py, Google Sheets 서버 연동, 80개 맵, 생애 스토리 8개 챕터, 메인 길찾기와 기존 에셋을 보존했다.

## 구현

- quiz.firstAttemptResults에 문제별 첫 응답의 정답 여부를 저장한다. 재도전과 정책 적용은 이 값을 바꾸지 않는다. 시도·자동 표시 힌트 횟수·완료 여부·적용 정책은 기존 별도 필드를 유지한다. crisis.performance에서 필수 문제만의 성취도와 주제를 집계한다.
- 실제 필수 ID는 q01~q08, q10~q12, q15다. q09, q13, q14는 보충 문제이며 최초 정답 수에 포함하지 않는다.
- 기존 저장에 최초 결과가 없으면 추정하지 않고 ‘최초 기록 없음’으로 표시한다. 이미 시도한 문제를 다시 풀어도 새로운 첫 결과를 만들어내지 않는다. 과거 최초 결과는 원본에 없으므로 복원할 수 없다.
- 완료 수와 최초 정답 수를 분리했다. 0~12개 모든 경계값에서 기본 단계는 10~12→1, 7~9→2, 4~6→3, 0~3→4다. 중간에는 실제 답한 문제만의 정답 비율을 사용하며 챕터 진행에 따라 위기 압력을 점진적으로 반영한다.
- 최종 단계에는 기존 인구 활력·경제·공동체·사회 안전망·환경·가족 지원 지표와 정책 실행을 함께 반영한다. 정답 수는 현실 인구 예측이 아닌 가상 사회 대응 준비도다. 높은 성취도에서도 사회 지표 악화로 위기가 발생하며, 낮은 성취도에서도 정책으로 회복할 수 있다.
- 상태는 저장된 퀴즈·지표·정책에서 결정적으로 계산한다. 언어 변경과 렌더링은 점수를 수정하지 않는다.
- buildings-ruin.png의 16종 건물과 school-ruin.png를 원본 화풍을 참고해 새로 제작했다. 학교의 ㄱ자 외형과 건물 위치는 그대로 사용한다. 원본 PNG는 덮어쓰지 않았다.
- 쇠퇴 단계에는 선택한 건물부터 변형을 사용하며 폐허 단계에서 훼손 건물의 범위를 넓힌다. 창문 파손, 외벽 손상, 낡은 지붕, 폐업 셔터, 도로 균열, 잡초, 낡은 비품 등을 별도 픽셀 오버레이로 추가한다. 신규 PNG 로딩 실패 시 원본 이미지와 절차적 오버레이로 대체한다.
- 회복 정책의 종류와 위치에 따라 의료·돌봄, 청년 주거, 세대 학습 시설, 벤치, 보행환경이 달라진다. 회복 후에도 일부 균열을 남긴다. 학습장에서는 완료했지만 미적용인 정책을 나중에 실행할 수 있다.
- NPC 수와 사회 대응 대사가 변한다. 메인 퀘스트 NPC와 마지막 학교 회고 인물은 항상 보존한다. 환경 오버레이는 solid 배열과 출입구를 수정하지 않는다. 폐쇄는 사용하지 않는 일부 시설의 시각적·서사적 상태이며 주요 공간은 계속 이용할 수 있다.
- 실제 게임과 엔딩은 같은 위기 계산, 변형 에셋과 환경 계획을 사용한다. 15세 비교는 원래 지도·에셋, 65세 비교는 현재 최종 상태로 그린다. 엔딩을 다시 열면 이전 캐시 이미지 대신 정책 변화까지 반영한다.
- 한국어·러시아어 결과 문구, 학교 변화 안내, 최초 기록과 성찰, NPC 추가 대사를 지원한다. 방향 조작 등 주요 접근성 속성도 언어 전환 시 번역한다.

## 디버깅·성능

시작 전 목표 안내가 먼저 story를 만들 때 부분적인 life 객체가 생겨 history.length에서 렌더링이 멈추던 문제를 수정했다. 생애 상태의 기본값을 보완하면서 기존 story를 보존한다. 초기 프레임 오류도 진단 로그에 남도록 개선했다.

환경 계획은 지도·위기 단계·적용 정책이 바뀔 때만 재계산한다. 매 프레임 전체 맵을 생성하지 않는다. 기존 공간 인덱스와 지도 캐시를 유지한다. 환경 표현 이후 인물과 별표를 표시해 가려지는 문제를 줄였다.

## 검증 결과

- JavaScript 테스트 12개 파일 전체 통과. 원래 200개 생애 선택 경로 테스트들을 유지했고 v5.3 전용 260개 완주 경로를 추가했다. 실제 테스트 로그는 v53-javascript-tests.txt에 포함했다.
- Python 검증·인증·SQLite 저장·복원 테스트 17개 통과. 첫 응답 boolean 검증, 옛 저장 호환, 훼손 데이터 거부 테스트를 추가했다. 로그는 v53-python-tests.txt에 포함했다.
- 첫 정답 0~12개 전체 경계, 반복 오답, 재도전 완료, 미응답 제외, 낮은 성취도+회복, 높은 성취도+사회 위기, 저장 JSON 검증, 정책 중복 방지, 환경 캐시와 충돌 데이터 불변을 검증했다.
- 실제 브라우저 화면에서 12→1, 9→2, 6→3, 0→4단계를 확인했다. 폐허 학교 출입과 노란 목표 별표, 네 장 엔딩 비교 이미지, 러시아어 결과 문구, 회복 4→1과 최초 정답 0개 보존, 저장·불러오기 후 동일 상태를 확인했다.
- 데스크톱 화면과 1024×768 태블릿 크기에서 표시·스크롤·조작 UI를 확인했다. 관찰 시 FPS 표시는 약 59~60이었다. 이는 현재 PC 브라우저 측정이며 실제 iPad/Android 성능을 보증하지 않는다.
- 테스트 환경의 Node 워커 실행 제한 때문에 파일별 node --test --test-isolation=none으로 실행했다. Python의 Windows 임시 폴더 생성 권한 문제는 작업 폴더 내부의 테스트 전용 디렉터리를 사용해 해결했다. 제품의 저장 권한이나 보안 설정은 바꾸지 않았다.

## 실행·추가 확인

기존 README 절차대로 pip install -r requirements.txt 후 streamlit run app.py를 실행한다. Google Sheets 비밀정보는 기존 .streamlit/secrets.example.toml을 참고한다. 실제 Sheets 계정 통신과 Streamlit 통합 서버 실행은 이 환경에서 확인하지 못했다. 서버 저장 로직은 자동 테스트로 검증했다.

개발용 정적 화면은 components/rpg_game에서 python -m http.server 8765로 실행할 수 있다. ?test&qa-v53에서는 경계값·폐허·회복·엔딩 검증 버튼을 제공한다. 일반 플레이 URL에는 검증 버튼이 나타나지 않는다. 이 검증 모드는 테스트 저장을 새로 만들므로 실수업 학생 기록과 분리해서 사용한다.

태블릿 실물 기기와 학교 배포 환경에서 한 차례 전체 수업 흐름을 점검하는 것이 남아 있다. 설치된 원본 의존성 목록과 기존 배포 방식은 유지했다.
